# Huashu direction study

Six bounded candidates were considered against the existing game/UI and one update task. No stock imagery or copied dashboard was needed. The three full concepts are in `directions.html`; the remaining three are thumbnails below them. One main concept plus two light variants is used under Huashu's reduced-runtime route. No agent delegation or new prototype service is introduced.

1. **Field kit:** existing Revamped colors, one release/version band, quiet folder row, fixed action at the bottom. The hourglass is the only prominent graphic. The hierarchy comes from update state rather than generic cards. Preferred for native implementation.
2. **Android utility:** conventional slate surface, restrained availability banner, stacked release information and standard Android controls. Useful calm alternative, weaker game identity.
3. **Release journal:** pale surface, typographic changelog focus and compact version header. Strong readability, but less continuity with the game's night palette.
4. **Foldable split:** folder/installed information in a left rail and release details on the right. Reserved as a thumbnail; too much structure for the narrow-phone case.
5. **Launcher tile:** enlarged hourglass and large update number with compact details underneath. Rejected as a thumbnail because the symbol displaces useful release text.
6. **Compact list:** Android settings-style rows with the available release as the main list item. Efficient, but too little hierarchy for failure/recovery states.

Form comes from the actual operation: installed and available versions are a comparison, release notes explain the change, and one action advances the workflow. Native implementation must retain these relationships rather than copy CSS literally.
