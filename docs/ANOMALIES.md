# Additional findings from the burn investigation

- A12 — Burn lifetime changed materially between platforms. Confirmed static code: Windows independently expires each additive application after its own duration; Android accumulates damage in a shared BurnBuff and refreshes its remaining tick count on reapplication. Android's shipped level2 scene caps burn damage at 1000 per tick before Health processing, overriding the constructor's 100. Impact: copying only burn percentages or assuming a pure optimization would change sustained-fire balance.   A13 separately corrects proven query truncation. Evidence: evidence/fire-behavior/README.md and fire-arm64.json.
- A13 — Confirmed reachable Combustion field query truncation, corrected. Native Flame Cannon → level-20 Combustion choice → three real Health kills spawns PF_BurningField/PersistentBurn (component 5990). S3/run-30 verifies five live test enemies all overlap the query, yet only one receives a burn: the native two-collider buffer truncates six collider results. Android PeriodicallyBurnArea uses a growable ID list and GetInRadius scans all registered transforms without this cap. src/BurnAreaCoverage.cs replaces only the Windows physics query with a dynamically enlarged, component-owned reusable buffer; the native timer and Burn loop remain intact. S3/run-32 burns all five known enemies on the first pass, retains damage 3 / interval 0.5 seconds and exits the native scene without exceptions. Collider-overlap geometry and Windows stacking/lifetimes are retained. Earlier runs 28/29 exposed fixture assumptions about pool parenting / distinct targets per collider; run-31 used the previous binary after a compile failure and is not corrected-code evidence. The runner now rejects binaries older than compiled source. Source: evidence/fire-behavior/README.md, fire-arm64.json and exact native asset IDs.

- A14 — Confirmed native pooled-summon teardown defect. Native Katana/Magic Bow scene exit in evidence/S3/run-13 fails with SeekerWeapon.OnDestroy; run-14's bounded reproduction logs unused PF_MagicSword pool members inactive with Summon.stats null immediately before each exception. Summon.Start assigns stats and calls Init, which subscribes to the attack-speed event; unused pool members never run Start, yet OnDestroy dereferences the property to unsubscribe. src/SummonLifecycle.cs skips only teardown of never-initialized members and retains original unsubscribe for initialized instances. run-15 verifies native scene exit with both one initialized and 29 unused members, no exceptions. Android 8.6 OnDestroy still calls get_summonAtkSpdMod, but that getter uses the global current player; its native lifetime ownership must be reconciled. Source-linked ARM ranges: evidence/S3/lifecycle-arm64.json/.txt. No combat or balance values changed.

- A15 — Confirmed native choice-generation completion hazard, bounded correction alongside new fallback perks. Windows GetRandom uses rejection sampling until it finds the requested number of distinct eligible choices, even if fewer exist. run-24's invalid fixture pool demonstrated that mechanism; ordinary/endless pool depletion can reach the same condition. Android adds six fallback entries and excludes them until regular eligible candidates are fewer than requested, but its inspected Init/Remove paths still give them finite map counts. src/FallbackPowerups.cs retains that source selection policy and counts, supplies actual eligible candidates to native selection, temporarily reduces native level-up choice slots when needed, restores the count on exit, and skips impossible fully exhausted level-up/fallback-chest transitions. run-37 verifies actual native full/depleted/single-choice offers, finite exhaustion, continued combat, and native exit/restart. It does not claim a naturally played 100-plus-level exhaustion run or a verified Android runtime freeze. No existing perk balance values changed.

## Existing-perk behavior differences found in the native-body audit

- A44 — Splinter changes inherited projectile size and its activation limiter. Windows' radial action multiplies the gun recipe size by 0.5 and limits that action to three activations per frame. Android ShootBulletsOnDeath's coroutine (0x198923c) assigns recipe size=0.5 outright; its OnDeath (0x19890b0) and coroutine use one static currentBullets counter shared across instances, incremented/decremented around yielding work. The base three-projectile / 15%-damage recipe remains.

- A43 — Android Shatter loses the documented frozen-target guard in the inspected build. Windows ShatterFrozenAction.Activate checks FreezeSystem.IsFrozen before spawning its explosion. Android IceShatterOnDeath.Start (0x1899c90) subscribes to Health.DeathEvent, and OnDeath (0x1899ea0) spawns/sets percentage damage without checking frozen state. Health.Death (0x197dea4) posts that event for any notified non-player death, before pool release; it has no freeze-only filter. Static consequence: the source handler also processes unfrozen enemy deaths, unlike Windows' documented effect.  This is an inspected source path, not an Android runtime playtest. A39 separately records repeat strength changes.

- A39 — Several rewritten repeat effects no longer use Windows' distinct first/stack recipes. Windows Frostbite has 15% ordinary-enemy damage initially and 10% per extra pick; Shatter has 7% initially and 5% per extra pick. Android attaches another helper with the original 15% / 7% fields on each repeated application. Ghost Wizard assigns GhostFriend's bulletEffect=true / BurnDameage=6 on Android, rather than adding another Windows summon-hit trigger/action pair.  These are source contract differences, not measured whole-run balance or automatically approved fixes.
- A40 — Gale/Eye of the Storm change geometry despite similar descriptions. Windows Aero Magic uses a two-second PeriodicTrigger with an already-correct current suffixed description; its throw action uses an 80-degree total spread. Android GaleSystem.Create (0x19736f0) chooses an integer angle from -60 to 60 around ShootDir and spawns PF_Gale at player position. Eye of the Storm enables DurationDamageBuff on that moving PF_Gale: sharedassets2 ID 231 specifies radius 3 / two-second ticks / 2x Gale damage, and Update (0x1985f78) queries around its own transform. Windows' periodic AreaTargetAction is centered on the player with range 5.  The unused older description key is stale, but no current tooltip correction is required.
- A41 — Electro Mage's target selection is adapted for mobile. Both recipes retain one 22-damage lightning strike every two shots. This is an explicit platform adaptation disposition, not a ported targeting feature.
- A42 — Sword and Shield's completion boundary differs. Windows SmiteHolyShieldCDR adds one second to an inactive shield's elapsed recovery timer. Android's corresponding callback (0x18a3c20) subtracts one from the scheduled apply time through ReduceApplyTime (0x19621e0), but if it crosses the current game clock it clamps the next apply to current time +1 second.

- A38 — Summon growth/composition changes beyond base recipe values.
