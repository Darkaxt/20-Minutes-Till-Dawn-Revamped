# Appearance collection

Authorization: the user requested a tab comparable to Runes, selecting each character/weapon's available skin, with related cosmetics unlocked by successful runs. Cosmetics are included independently of Android purchases, passes and lotteries. Existing gameplay, progression and saves must be preserved.

## Required behavior

- C01: An Appearance tab sits beside Runes in character/weapon selection. It uses native pixel-art panels, type, buttons and selection cues, opaque menu backgrounds and complete controller/pointer navigation. Back returns to the originating selector and restores focus. At 1280×720, 1920×1080 and square aspect ratios, controls, preview and descriptions remain inside the panel.
- C02: Select an unlocked character skin and wing for each character, and an unlocked weapon skin for each weapon. Original appearance/No wings are always available. Selections and collection persist without changing rune ranks, familiarity, ownership, scores or existing saves. Bullet-colour choices from the source catalog are included as an optional appearance selection.
- C03: One successful eligible run grants one previously unowned cosmetic related to the played character (character skin or related wing), and one previously unowned skin for the played weapon, while eligible items remain. Use the actual source associations; a selected reward is automatically recorded and announced. Custom remains excluded, consistent with its existing no-unlocks contract. Do not invent historical wins from highest-clear records or reset profiles. Replay of one completed run must not duplicate rewards.
- C04: Carry the supplied 8.7 character, summon, ability, gun, projectile and wing artwork/animations through preview, fresh runs, pooled objects, weapon evolutions, Retry and Continue, retaining the selected original/Reborn art mode where applicable. Appearance must not change damage, hitboxes, stats or skill counts. All source cosmetic catalog entries must have an explicit disposition; default colour entries are not counted as new art.
- C05: Prepare proprietary artwork locally from the user's Android package(s); distribute only code/recipes. Integrate installer preparation, package contracts and the existing Android updater delivery. Preserve existing game/profile data. No phone deployment is requested by this task.
- C06: Verify rewards/persistence/Continue/controller flow and representative character/weapon/wing animations in an isolated background Windows player. Update README/install instructions and publish one verified final game release after the complete cosmetic integration passes.

## Design contract

Preserve the existing dark purple opaque panels, cream body text, pink headings, green muted text, native focus arrow and pixel-filtered artwork. Appearance opens from a real navigation button beside Runes, with Character / Weapon / Wings / Bullet colour sections. The main region contains a paged icon grid and a generous live preview; locked entries remain browsable and state the simple victory requirement. Selected entries have an explicit equipped cue. No storefront, prices or floating debug panel. Responsive layout uses the game's existing canvas and reference coordinates.
